## Generation Policy Cleanup Dev Spec

This record defines the forward ProteinMPNN generation-policy path for Eco1 RT
repacking. The v3 path uses complete generation policies, residue-level
alphabet sidecars for near retained DNA/RNA positions, and full downstream
fold/local-structure review before selection.

The key implementation boundary is simple:

```text
ProteinMPNN outputs are complete sequences sampled under one declared policy.
Do not combine mutations from different ProteinMPNN outputs after generation.
```

If a study needs a variant that combines near retained DNA/RNA changes with
distal scaffold changes, define one upstream policy that opens both sets of
positions and let ProteinMPNN design the complete sequence under that policy.

### Alignment Check

This spec carries forward the source-note decisions as follows:

| Source-note decision | Spec treatment |
| --- | --- |
| ProteinMPNN outputs are complete sequences, not mutation bins. | Candidate rows must carry one generation policy provenance record; combined proximal plus distal hypotheses are generated by `combined_near_acid_free_plus_distal_v1`, not assembled after generation. |
| Replace nested distance masks as the main story. | The active primary path uses explicit generation policies, not nested distance classes. |
| Protect evidence-backed functional geometry. | Motif contexts, direct retained DNA/RNA contacts, Wang thumb-track positions, conserved/core positions, and mapped C-terminal/thumb context `255-311` are fixed in every primary policy. |
| Allow conservative proximal chemistry. | The near retained DNA/RNA policy opens only `>5 A` and `<=10 A` positions outside the protected set and disallows acidic gains. |
| Use distal positions for mutation count and diversity. | The distal policy opens mapped scaffold positions outside protected and near-region contexts. |
| Select by safe mutation coverage. | Final selection maximizes newly covered safe positions and substitutions after hard gates; total mutation count is only a tie-break. |
| Keep RMSD as a preservation gate. | The spec keeps local RMSD as a gate and explicitly rejects loosening RMSD to recover candidate count. |

### Objective

Redefine the Eco1 RT ProteinMPNN mask system as explicit generation policies,
regenerate the full candidate pool, and select a new protein-only review panel
from complete ProteinMPNN-designed sequences.

The intended premise is:

```text
Select fixed-backbone Eco1/Ec86 RT protein hypotheses that preserve catalytic,
retron-initiation, direct nucleic-acid-contact, Wang thumb-track,
C-terminal/thumb, and local structural contexts while improving safe mutation
coverage and sequence diversity.
```

This is not an activity claim, processivity claim, strand-displacement claim, or
thumb-track tuning claim. Selected variants are protein hypotheses for later
testing.

### Non-Goals

Do not implement:

- compatibility shims for previous mask names;
- fallback paths that silently reinterpret previous mask configs;
- post hoc mutation composition across masks;
- nested `5 A / 6 A / 8 A / 10 A` distance masks as primary generation
  policies;
- minimum mutation-count quotas;
- required numbers of proximal-basic variants;
- composite processivity scores;
- direct Wang thumb-track mutation as ordinary design behavior;
- RMSD loosening to recover candidate count.

Generated outputs without matching v3 policy provenance are stale for this path.
The pipeline must not mix candidate pools with different policy manifests.

### Terminology

Use explicit policy terms in code, configs, manifests, notebooks, and docs.

| Term | Meaning |
| --- | --- |
| `protected_positions` / `fixed_positions` | Residues ProteinMPNN must not redesign. |
| `open_positions` / `designable_positions` | Residues ProteinMPNN may redesign. |
| `generation_policy` | One complete ProteinMPNN design contract: fixed residues, open residues, and residue-level alphabet constraints. |
| `allowed_amino_acids` | Per-position or per-region amino-acid choices, when supported by the generation path. |
| `policy_id` / `policy_version` | Stable policy identity and version written into candidate provenance. |

Avoid ambiguous language such as "mask composition" or "merge proximal and
distal mutations."

### Shared Protected Set

Every primary policy must use the same protected-position builder. The builder
owns the fixed set; each policy only chooses which remaining positions are open.

Always fix:

| Region | Rule |
| --- | --- |
| Catalytic/retron motif context | Eco1 `99-115`, `189-204`, and `237-251`. |
| Direct retained DNA/RNA contact shell | Mapped residues within `<=5 A` of retained DNA/RNA. |
| Wang thumb-contact track | Eco1 positions `238,239,240,249,257,261,264,298`. |
| C-terminal/thumb primer-RNA recognition context | Mapped Eco1 positions `255-311`. |
| Conserved/core residues | Positions passing the declared MSA conservation/core mask. |

The C-terminal/thumb context is protected in the primary policies because
Inouye 1999/2004 supports treating the Ec86 C-terminal/thumb region as a
primer-RNA recognition context. Wang/7V9U supports preserving observed RT-msDNA
/ msrRNA interface geometry and tracking the electropositive substrate-facing
surface. These sources justify caution; they do not define a functional score.

The protected-position builder must emit a manifest table with at least:

```text
eco1_position
structure_position
chain_position
is_mapped
is_designable_backbone_position
protected_reason_codes
distance_to_retained_dna_rna
is_direct_contact_le_5a
is_near_region_gt5_le10a
is_wang_thumb_track
is_c_terminal_thumb_context
is_conserved_core
```

A position may have multiple protected reasons. Missing protected reasons are
errors, not warnings.

### Primary Generation Policies

Implement exactly these three primary policies for the planned regeneration.

#### `distal_scaffold_repack_v1`

Purpose: increase mutation count and sequence diversity without claiming
substrate-interface tuning.

Open positions are mapped residues outside:

- motif contexts;
- direct retained DNA/RNA contacts;
- near retained DNA/RNA region `>5 A` and `<=10 A`;
- Wang thumb-track positions;
- C-terminal/thumb context `255-311`;
- conserved/core positions.

Allowed amino acids:

- broad ProteinMPNN choices;
- preserve the existing no-new-cysteine policy if present;
- no substrate-facing chemistry claim.

The current notes suggest roughly 29 strict non-C-terminal distal positions in
the existing evidence frame, including ranges such as `3-11`, `13-16`, `20`,
`22`, `24-26`, `28-29`, `31-32`, `61`, `75`, `79`, `110`, `191`, `201`, and
`203`. Treat these as a sanity check, not a hard-coded list.

#### `near_dna_rna_acid_free_v1`

Purpose: conservatively sample substrate-facing chemistry outside direct
contacts.

Open positions are mapped residues:

- `>5 A` and `<=10 A` from retained DNA/RNA;
- excluding motif contexts, direct contacts, Wang thumb-track positions,
  C-terminal/thumb context `255-311`, and conserved/core positions.

Allowed amino acids:

- WT;
- MSA-observed acid-free alternatives;
- no D/E acidic gains, enforced upstream through ProteinMPNN `omit_AA_jsonl`;
- no Pro/Gly gains in the near retained DNA/RNA shell unless the WT residue is
  already Pro/Gly.

The current notes suggest roughly 68 non-C-terminal near-region positions before
alphabet filtering. Treat that count as a sanity check, not a requirement.

Alphabet enforcement must be explicit. V3 near and combined policies materialize
public ProteinMPNN `omit_AA_jsonl` sidecars from
`generation_policy_alphabets.parquet`; downstream chemistry gates remain review
checks, not the only mechanism enforcing acid-free sampling.

#### `combined_near_acid_free_plus_distal_v1`

Purpose: generate complete variants that jointly design conservative proximal
chemistry and distal scaffold diversity.

Open positions are the union of:

- `distal_scaffold_repack_v1` open positions;
- `near_dna_rna_acid_free_v1` open positions.

Allowed amino acids:

- distal positions: broad ProteinMPNN choices, subject to global exclusions such
  as no-new-cysteine;
- near DNA/RNA positions: WT plus acid-free, preferably MSA-supported
  basic/polar/neutral alternatives.

This policy must be generated upstream as a single ProteinMPNN policy. Do not
create combined variants by merging mutations from distal-only and near-only
outputs.

### Non-Primary Policy Classes

Nested distance/conservation stringency classes are not primary policy classes
in the v3 run. They must not be runnable defaults, hidden fallbacks, or implicit
selectors in this policy version.

Do not include a C-terminal boundary policy in the primary regeneration run. If
that becomes useful later, treat it as a separate exploratory policy, not part
of the conservative panel.

### Config Shape

Use a policy-first schema. This example is illustrative; code should define the
actual schema in the owning materializer/config module.

```yaml
eco1_rt_repack:
  generation_policy_version: 3

  protected_set:
    motif_contexts:
      naxxh: [99, 115]
      yadd: [189, 204]
      vtg: [237, 251]
    direct_contact_distance_angstrom: 5.0
    near_region_distance_angstrom:
      min_exclusive: 5.0
      max_inclusive: 10.0
    wang_thumb_track_positions: [238, 239, 240, 249, 257, 261, 264, 298]
    c_terminal_thumb_context: [255, 311]
    use_declared_msa_conserved_core_mask: true

  global_alphabet_rules:
    disallow_new_cysteine: true

  generation_policies:
    distal_scaffold_repack_v1:
      enabled: true
      requested_variants: 336
      open_set: distal_scaffold
      alphabet: broad

    near_dna_rna_acid_free_v1:
      enabled: true
      requested_variants: 336
      open_set: near_dna_rna_gt5_le10_excluding_protected
      alphabet: msa_observed_acid_free_basic_polar_neutral

    combined_near_acid_free_plus_distal_v1:
      enabled: true
      requested_variants: 336
      open_set:
        union:
          - distal_scaffold
          - near_dna_rna_gt5_le10_excluding_protected
      alphabet_by_region:
        distal_scaffold: broad
        near_dna_rna_gt5_le10_excluding_protected: msa_observed_acid_free_basic_polar_neutral

  generation_total_target_raw: 1008
```

If the actual ProteinMPNN run matrix has seed, temperature, or command-bin
subdivisions, distribute requested variants across concrete bins while keeping
the same total target. Do not add adaptive "fill until 1000 unique" behavior.
Generate the requested pool, deduplicate, and report the actual unique count.

policy schemas. If a helper can be shared, promote the neutral part behind a
typed function and keep Eco1 policy semantics in the study-owned package.

Current implementation target:

- `generation_policy_version` is `3`.
- The active output root is `generation_policies_v3/`.
- The policy/request writer emits one request subtree per complete policy and
  records `policy_id`, `policy_version`, and `policy_manifest_hash`.
- Near and combined policies emit ProteinMPNN `omit_AA_jsonl` sidecars for
  residue-specific near-region alphabets.
- The BU SCC submit template maps array tasks to complete generation policies
  and runs ProteinMPNN sample ingest plus candidate-table materialization for one
  policy at a time.

### Provenance And Identity Rules

Every raw generated sample row must have exactly one `policy_id`, one
`policy_version`, and one `policy_manifest_hash`. Deduplicated sequence rows may
record `source_policy_ids` and `source_sample_ids`, but they must still choose a
single deterministic `primary_policy_id` for reporting. This records provenance;
it does not merge mutations.

Candidate ids should be generated from complete sequence plus policy/run
provenance. Do not encode backend paths or previous mask names into new ids.

### End-To-End Regeneration

For future regenerations, rerun the pipeline from policy/materialization through
selection and export.

Required stages:

1. build residue authority map;
2. build protected/open policy manifests;
3. materialize ProteinMPNN inputs per policy;
4. run ProteinMPNN generation;
5. parse generated sequences;
6. deduplicate exact protein sequences;
7. fold / structure-check generated candidates;
8. compute global fit and local RMSD by named region;
9. compute mutation geography and chemistry annotations;
10. compute MSA support fields;
11. apply hard preservation and chemistry/support gates;
12. select final panel by safe mutation coverage;
13. export selected panel, audit tables, plots, manifest, and RT-only FASTA /
    sequence outputs.

RMSD remains a preservation gate, not a design dial. Do not loosen RMSD
thresholds to recover candidates.

### Staleness Handling

Any artifact depending on old mask definitions must be invalidated.

Add `generation_policy_version` and `policy_manifest_hash` to downstream
candidate tables. Pipeline stages must fail fast if candidate tables were
produced under a different policy manifest.

No fallback behavior should silently load old parquet, CSV, or YAML outputs.

### Regeneration Preflight

Before a v3 regeneration, the implementer should confirm:

If any of those checks fail, update the study record first rather than starting
from stale assumptions.

### Selection Spec

Keep the selection story to three stages:

1. preservation/fold gates;
2. chemistry/support gates;
3. final panel selection.

Hard-gate failures:

```text
not strong_fold
protected/core/direct-contact edit count > 0
wang_thumb_track_edit_count > 0
any named local RMSD gate fails
near_region_acidic_gain_count > 0
proximal_unobserved_substitution_count > 0
```

Final selection should choose complete candidates by incremental safe mutation
coverage:

1. maximize newly covered mutated positions versus the already selected panel;
2. maximize newly covered exact substitutions versus the already selected panel;
3. prefer higher total mutation count only as a coverage tie-break;
4. penalize near-region basic losses;
5. penalize Pro/Gly gains in structured elements;
6. prefer stronger region-wise MSA support;
7. use fold/local RMSD metrics inside gates and as late tie-breakers only;
8. use deterministic final tie-breakers.

Do not use raw mutation-count quotas, required proximal-basic lanes, processivity
scores, or post hoc mutation assembly.

### Tests

Policy builder tests:

- catalytic/retron motif context positions are protected;
- direct retained DNA/RNA contacts `<=5 A` are protected;
- Wang thumb-track positions are protected;
- C-terminal/thumb context `255-311` is protected in primary policies;
- conserved/core mask positions are protected;
- near-region policy excludes direct contacts and C-terminal/thumb positions;
- distal policy excludes near-region and protected positions;
- combined policy open set equals the union of distal and near open sets, not
  post hoc mutation merging.

Alphabet tests:

- near-region policy forbids D/E gains;
- near-region policy only allows WT plus MSA-observed acid-free
  basic/polar/neutral alternatives when per-position alphabets are available;
- Pro/Gly gains are disallowed or penalized according to the current
  structured-element implementation;
- distal policy uses broad ProteinMPNN alphabet subject to global exclusions;
- no-new-cysteine behavior is preserved if currently implemented.

Staleness tests:

- old mask identifiers cannot be used in the new primary config;
- downstream stages reject candidate tables with missing or mismatched
  `generation_policy_version`;
- no compatibility adapter silently maps old `contact8a/contact10a` masks to
  new policies;
- generated outputs include `policy_manifest_hash`.

Selection tests:

- hard-gate failures cannot be selected;
- acidic near-region gains fail selection;
- Wang thumb-track edits fail selection;
- proximal unobserved substitutions fail selection;
- selector prefers new mutated-position coverage before total mutation count;
- selector prefers new exact-substitution coverage before total mutation count;
- deterministic tie-breaks produce stable selected panels.

End-to-end smoke test:

- use reduced requested variants per policy;
- generate policy manifests;
- generate ProteinMPNN inputs per policy;
- confirm candidate rows carry policy ids and manifest hashes;
- run through selected-panel export;
- confirm selected outputs cite policy version and manifest hash;
- confirm no old mask output is loaded.

### Acceptance Criteria

The cleanup is complete when:

1. the old primary mask family is removed from the active generation path;
2. the three new policies are the only default primary generation policies;
3. no post hoc mutation merging exists;
4. ProteinMPNN is run separately per complete policy;
5. the total requested raw variant count is approximately 1000, for example
   `336 x 3 = 1008`;
6. regenerated outputs are produced from the new policy manifest;
7. candidate tables include `policy_id`, `policy_version`, and manifest hash;
8. the selected panel is produced only from candidates generated under the new
   policy version;
9. the final selector uses safe mutation coverage, not mutation-count quota;
10. reports disclose requested, generated, deduplicated, fold-passed,
    chemistry/support-passed, and selected counts by policy;
11. the selected panel has zero protected edits, zero Wang thumb-track edits,
    zero direct-contact edits, zero near-region acidic gains, and zero proximal
    unobserved substitutions;
12. docs and notebooks use "protein hypotheses," not "processivity hypotheses";
13. ESMC/SAE are presented only as annotations/checks, not selection evidence;
14. stale outputs fail fast rather than feeding the new pipeline.

### Implementation Note

New policies can be compared downstream, but final variants must be complete
sequences produced by ProteinMPNN under one policy. The combined proximal plus
distal design space must be sampled by the combined upstream policy, not
constructed from separate proximal-only and distal-only candidates.
