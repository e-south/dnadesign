## Temporary privacy allowlist

Two generated retron-hairpin provenance files contain legacy absolute local
paths. They remain tracked scientific outputs and must be regenerated by their
owning producer rather than edited by hand:

- `docs/studies/retron_hairpin_design/workbench/provenance/msd_region_records/reader_spop_msd_structure_panel_v1/manifest.yaml`
- `docs/studies/retron_hairpin_design/workbench/provenance/msd_region_records/reader_spop_msd_structure_panel_v1/reports/discrepancies.yaml`

The privacy check allows only the known `personal_macos_home` path signature at
those exact paths through 2026-09-30. Personal email, SCC login, SCC project
paths, and every other signature still fail there. The check also scans every
other provenance document, so a new path-bearing file fails immediately. The
allowance itself fails after the expiry date, even if the files no longer
contain a matching signature; this prevents a stale exception from becoming
permanent.

The residual risk is limited to path metadata that was already present in the
public history. Regeneration does not retract copies, forks, or caches.

The owning producer is the retron-hairpin MSD-region ingest surface implemented
by
`dnadesign.studies.units.retron_hairpin_design.interfaces.cli.msd_region_ingest`.
Regenerate these artifacts through its `ingest-msd-regions` command into a
fresh output root, validate the result, replace the generated bundle as one
unit, and then delete the matching allowance entries from
`dnadesign.devtools.security.tracked_text_privacy`. Do not hand-edit the
manifest or discrepancy report.
