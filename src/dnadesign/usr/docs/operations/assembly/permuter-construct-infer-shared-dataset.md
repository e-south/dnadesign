## Permuter -> Construct -> Infer Shared Dataset Runbook

**Type:** runbook
**Plane:** data-plane
**Owner-boundary:** usr
**Entry artifact:** Permuter variant dataset or study-owned candidate envelope plus explicit Construct target
**Exit artifact:** construct-backed USR dataset ready for Infer sequence-view feature sidecars
**Registry-id:** usr.data-plane.permuter-construct-infer-handoff
**Summary:** Route Permuter-originated variants through study-owned promotion, Construct context realization, and Infer-owned sidecars without coupling tool internals.
**Execution-kind:** staged
**Status-kind:** usr-dataset-state

**Owner:** dnadesign-maintainers
**Last verified:** 2026-05-24

Use this runbook when variants generated by Permuter need model features in a
Construct context. The durable boundary is still a USR dataset. Permuter does
not write Infer sidecars, Construct does not generate variants, and USR does
not reinterpret study candidate ids as canonical sequence ids.

### Boundary decisions

- Permuter owns variant intent and `permuter__var_id`.
- USR owns canonical sequence `id`, overlays, events, and sidecar locations.
- Study code owns biological promotion from variants into candidate envelopes.
- Construct owns named-slot realization and sequence views.
- Infer owns feature-bundle execution and `_derived/infer` payloads.
- Ops only discovers and executes declared lanes; it does not infer hidden study
  readiness.

### Ordered procedure

1. Generate variants through the public Permuter facade.
   - Use `dnadesign.permuter.generate_variants(...)`.
   - Use `materialize_result(...)` only when the Permuter dataset itself is the
     handoff artifact.
   - Verify materialized rows have canonical USR `id` and `permuter__var_id`.
2. Promote variants into a study-owned candidate envelope when biological context
   is needed.
   - Keep candidate identity in a namespaced field such as
     `candidate__candidate_id`.
   - Keep slot biology in explicit fields such as `candidate__lnrna_sequence`
     and `candidate__rt_cds_sequence`.
   - If the base `sequence` column is only an envelope carrier, mark it with
     `candidate__record_kind=candidate_envelope` and
     `candidate__sequence_authority=overlay_only`.
3. Run Construct against the candidate envelope.
   - Use named slots and explicit sequence fields.
   - Write realized sequences and sequence views to the shared output dataset.
   - Use `output.on_conflict=error` until rerun semantics are proven.
4. Run Infer against the Construct output dataset.
   - Select sequence views by explicit `view_name` or stable alias.
   - Run `infer validate sequence-view-completion` before long model jobs.
   - Let Infer write `_derived/infer` aliases and payloads.

### Fail-fast checks

- `uv run python -m dnadesign.devtools.architecture.boundaries --repo-root .`
- `uv run usr --root <usr-root> validate <candidate-or-output-dataset> --strict`
- `uv run infer validate sequence-view-completion --config <config.yaml> --mode inventory`

### Rejected patterns

- Copying study candidate ids into USR `id`.
- Writing `_derived/infer` from Permuter or Construct.
- Selecting RT-lnRNA views by broad `product_kind` plus orientation.
- Hiding multi-source or multi-tool assembly inside one Construct config.
- Adding duplicate variant-id columns for compatibility.
