# 2026-05-10 Native Reference Processing And Ontology Audit

## Question

Are `spyP` and `sulAp` processed differently from the other native MG1655
promoter references, and could that explain why their core60 rows behave more
like the expected ethanol and ciprofloxacin landmarks?

## Short Answer

Mechanically, no. `spyP`, `sulAp`, and the other native MG1655 promoter rows
come from the same `usr_promoter_references` GenBank-projected source dataset.
Their core60 rows are generated by the same Construct job, with the same
`annotation_pair_midpoint` focal rule, the same target length, the same
high-confidence focal annotations, and the same 1 kb forward/reverse-complement
context construction.

The important difference is semantic, not mechanical:

- `spyP` is annotated with BaeR and CpxR binding sites, which are the same
  regulator families used to define the ethanol-like DenseGen design axis.
- `sulAp` is annotated with LexA binding, which is the same regulator family
  used to define the ciprofloxacin/SOS-like DenseGen design axis.
- The broader native reference panel is biologically mixed: envelope stress,
  SOS, oxidative stress, mar/rob multidrug response, phosphate, carbon,
  amino-acid, and other global/metabolic regulators are all represented.

So the fact that `spyp_core60` and `sulAp_core60` look cleaner than the broader
native panel is not suspicious by itself. They are more directly aligned with
the study's two stress axes.

## Processing Parity

All native/legacy MG1655 source rows are primer-flank-stripped GenBank-projected
promoter inserts in `usr_promoter_references`.

All native core60 rows are produced in
`construct_prom_eth_cip_reference_core60` with:

- `derived__parent_dataset = usr_promoter_references`
- `derived__target_length = 60`
- `derived__focal_rule = annotation_pair_midpoint`
- `derived__focal_confidence = high`
- `construct__anchor_start = 0`
- `construct__anchor_end = 60`
- `construct__focal_part_length = 60`
- `construct__resolved_length = 60`
- `construct__orientation = forward`

All native core60 context rows are produced in
`construct_prom_eth_cip_reference_contexts` with one forward and one
reverse-complement 1 kb context per core60 row. The anchor interval is
`470:530` in emitted coordinates for both orientations, with the matched
forward anchor interval stored explicitly.

`spyP` and `sulAp` pass through the same path as `aceBp`, `cpxPp`, `pspAp`,
`umuDCp`, and the other native references.

## Grouping Foot Gun

The source dataset has 19 native/legacy MG1655 promoter rows:

`aceBp`, `alaSp`, `aldAp`, `araBADp`, `argCBHp`, `cpxPp`, `fadEp`, `inaAp`,
`katGp`, `marRABp`, `micFp`, `phoAp`, `ppcp`, `pspAp`, `pspGp`, `soxSp`,
`spyP`, `sulAp`, and `umuDCp`.

The current LatentDNA `reference_native_mg1655` set contains 16 of those rows.
It excludes `spyP` and `sulAp` because they are exposed as their own landmark
set. It also excludes `soxSp`, even though `soxSp` is a GenBank-backed native
reference with Sigma-70 and SoxR/SoxS annotations.

That means current Native MG1655 centroid plots are not an all-native-MG1655
centroid. They are a configured 16-row native panel. This is acceptable only if
the label is read as "Native MG1655 panel excluding dedicated landmarks and
soxSp." If the intended meaning is all native GenBank references, the
reference-set config should be updated or a new `reference_native_mg1655_all`
set should be added.

## Local Binding-Site Ontology

The local GenBank annotations support these coarse stress-axis reads:

| Promoter | Local annotated TFBS | Practical read |
|---|---|---|
| `spyP` | BaeR, CpxR | envelope stress; directly ethanol-axis-like in this study |
| `sulAp` | LexA | SOS/DNA-damage; directly ciprofloxacin-axis-like in this study |
| `umuDCp` | LexA | SOS/DNA-damage; ciprofloxacin-axis-like |
| `cpxPp` | CpxR | envelope stress; ethanol-axis-like |
| `soxSp` | SoxR, SoxS | oxidative/superoxide stress; adjacent but not identical to cipro/SOS |
| `katGp` | OxyR, FNR | oxidative/peroxide stress |
| `marRABp` | MarA, MarR, Rob, Fis, Cra | mar/rob multidrug-solvent and global regulation |
| `micFp` | OmpR, IHF, Rob, SoxS | outer-membrane/multidrug/oxidative response |
| `inaAp` | CpxR, SoxS, MarA, Rob | mixed envelope, oxidative, and mar/rob response |
| `pspAp`, `pspGp` | PspF, IHF | phage-shock/envelope-stress program, not the same as CpxR/BaeR |
| `aceBp`, `alaSp`, `aldAp`, `araBADp`, `argCBHp`, `fadEp`, `phoAp`, `ppcp` | mostly metabolic/global regulators | not direct ethanol/ciprofloxacin landmarks |

This ontology explains why `spyP` and `sulAp` can behave more cleanly than the
larger configured Native MG1655 panel. They were not processed differently;
they are biologically more aligned with the study axes.

## Current Bidir Core60 Margin Read

Using the bidirectional candidate's background-relative stress margins:

| Core60 set | Background | Ethanol | Ciprofloxacin | Dual |
|---|---:|---:|---:|---:|
| Configured Native MG1655 panel, 16 rows | 2 | 8 | 3 | 3 |
| All native GenBank references, 19 rows | 2 | 9 | 5 | 3 |
| `spyP`/`sulAp` landmarks | 0 | 1 | 1 | 0 |
| `soxSp` only | 0 | 0 | 1 | 0 |

So the larger panel is not actually "all ethanol." The configured 16-row panel
leans ethanol in the bidirectional core60 margins, but the all-19 set becomes
more mixed once `spyP`, `sulAp`, and `soxSp` are included.

## Recommendation

Keep `reference_spyp_sulap` as a landmark set, because those two rows are
useful sanity checks. Also add one of these clarifying changes:

1. Add `soxSp` to `reference_native_mg1655` and keep `spyP`/`sulAp` separate.
2. Add a new `reference_native_mg1655_all` set containing all 19 native
   GenBank-backed rows, including `spyP`, `sulAp`, and `soxSp`.
3. Rename the existing label to make its subset semantics explicit.

The safest option is option 2: preserve the current 16-row panel for continuity
and add an explicit all-native set for future centroid and dropdown audits.
